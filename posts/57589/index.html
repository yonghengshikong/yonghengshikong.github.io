从AI写文跑偏到自研叙事Agent：大模型底层思维与架构复盘（纯干货）

从AI写文跑偏到自研叙事Agent：大模型底层思维与架构复盘（纯干货）

前言：我为什么要系统学AI与Agent架构？

长期使用AI进行小说创作、游戏剧情开发的人，一定会遇到两个无解痛点：

1. 角色持续偏移、人设崩坏（OOC）：明明写好了人物档案、性格设定，写到长篇中后期，人物性格、说话方式、行为逻辑全部跑偏。

2. 剧情不受控、频繁幻觉：AI会凭空捏造过往经历、篡改人物关系、推翻已固定剧情、制造不存在的伏笔与角色。

最开始我以为是提示词写得不好、模型不够强。后来发现：问题根本不在模型，而在没有架构。

单纯调用LLM是「被动文本生成」，只有搭建Agent自治系统，才能实现：人物永不崩坏、剧情逻辑闭环、时间线自洽、角色随剧情动态成长。

本文记录我从零打通的大模型底层认知 + RAG架构 + 叙事Agent设计思维，完全重思维、轻代码，适合所有想做「可控AI创作系统」的开发者/创作者。

一、先破误区：绝大多数人用AI的方式，从底层就是错的

很多人使用AI的模式：

写人设 → 写大纲 → 粘贴prompt → 生成内容 → 发现跑偏 → 手动修改 → 重新生成

这是人工兜底的裸LLM模式，永远无法根治偏移，原因来自大模型的五大原生缺陷：

  • 无持久记忆：仅靠上下文临时记忆，长文本会稀释、遗忘早期设定

  • 无客观事实认知：只会概率续写，分不清“设定”和“编造”

  • 无自主校验能力：生成完不会自查是否违背人设、剧情

  • 无规划能力：复杂多角色、多支线任务只会混乱拼接

  • 无外部交互能力：无法主动读取档案、图谱、时间线

核心结论：大模型只是原材料，一致性、可控性全部需要上层架构补齐。

二、AI三层体系认知（所有架构的顶层根基）

彻底区分三个层级，从此不再混淆LLM、AI工具、Agent：

1. 基座模型层（底层原材料）

GPT、DeepSeek、通义千问等，本质是概率文本续写器。只负责逐字生成，无记忆、无判断、无逻辑、无约束。

2. 普通AI应用层（单向工具链）

结构化Prompt、基础RAG、简单工具调用、线性链式流程。

特点：单向执行、无自检、无闭环、无动态更新。可以缓解偏移，但无法根治。

3. Agent自治系统层（最终解决方案）

在模型外层搭建完整闭环系统，具备：记忆、规划、执行、评审、动态更新。

只有到这一层，才能实现「全自动、低偏移、可长线连载」的小说/游戏剧情生成。

三、人设偏移的底层真相：Token、上下文稀释与幻觉

1. Token与上下文窗口的硬限制

模型单次对话有固定Token上限，所有「人设+世界观+历史剧情+需求」平铺占用窗口。

长篇致命问题：文本体量碾压权重。

几万字剧情 + 少量人设混在一起，剧情文字体量远大于设定，模型注意力被剧情惯性带走，人设被稀释、遗忘，最终OOC。

2. 随机性（Temperature）的利弊

温度越高，创意越强、偏移越严重；温度越低，人设越稳、创意越僵硬。

叙事场景黄金规则：

  • 主线关键剧情：0.3–0.5（稳人设、稳逻辑）

  • 支线日常对话：0.5–0.7（保留创意）

  • 严禁高温度写长线主线

注意：调参只能缓解，不能根治偏移与幻觉。信息缺失时，温度为0也会编造内容。

3. 幻觉的本质：信息不足=自动编造

大模型不会说“我不知道”，上下文缺少关键人设、历史事件、关系约束时，会自动生成逻辑通顺的虚假内容填补空白。

所有剧情乱编、人设新增、关系篡改、时间线悖论，全部源于此。

四、RAG向量库核心原理（解决长篇遗忘的唯一方案）

1. 彻底纠正误区：向量不是压缩包

很多人误以为向量是“文字压缩”，完全错误。

向量（Embedding）是语义数字索引，不压缩、不修改原文、不进上下文。

RAG的核心价值不是压缩，是外置存储 + 按需精准召回：

  • 把海量人设、世界观、剧情、关系移出对话窗口，存在外部知识库

  • 写作时只召回「当前出场角色、当前相关剧情」

  • 无关资料永久不占用Token，彻底杜绝稀释

2. 叙事专属RAG分片规则（防遗漏、防混杂）

想要不跑偏，入库必须遵守单一信息原则：

  • 一条向量文档 = 单角色档案 / 单关键事件 / 单条人物关系 / 单条世界观规则

  • 禁止主线+支线多事件混杂存入同一条向量

  • 重大剧情转折、立场反转、羁绊变化，必须独立分片

3. 双检索兜底（杜绝漏召回）

纯向量语义检索会漏信息，必须双层保障：

  • 标签精准强制召回：当前出场角色的所有人设、关系强制拉入上下文

  • 向量语义补充召回：匹配相似场景、相似过往事件

五、分层Prompt约束思维：人为定义优先级

模型不会自动区分重要性，必须人工架构分层，优先级从高到低：

  1. 硬性世界观/角色底线（不可篡改）

  2. 已发生固定历史剧情（不可推翻）

  3. 人物关系图谱约束

  4. 当前写作需求

  5. 创意自由发挥

同时增加负面禁令区块，明确禁止：编造经历、篡改关系、OOC行为、推翻历史。

分层Prompt是事前约束、RAG是素材保障、参数是风控手段——三者都无法单独根治偏移。

六、普通RAG工作流的四大致命缺陷（必须升级Agent）

我最初搭建的「设定入库→章纲→生成正文」RAG工作流，依然存在四个无法解决的问题：

  1. 无自动评审：输入素材正确，输出依然可能细微偏移，只能人工审稿

  2. 无动态记忆同步：新增/修改剧情后，向量库、图谱、角色履历不会自动更新

  3. 无迭代闭环：出错只能手动重写，没有自动修正流程

  4. 无任务规划：多支线、长卷剧情需要人脑拆分，系统无法自主拆解

想要彻底解决，必须引入Agent五大核心组件。

七、叙事Agent核心架构（根治OOC的终极闭环）

1. Agent五大标准组件

  • 记忆系统：分层存储静态人设、时序剧情、关系图谱、错误反思

  • 规划器Planner：自动拆分长篇复杂剧情为主线、支线、单场景子任务

  • 执行器Executor：调度RAG检索、LLM生成、工具调用

  • 评审器Critic（核心兜底）：独立LLM不创作、只审核

  • 更新器Updater：剧情变动自动同步全库数据

2. 双Agent协作架构（小说/游戏最优解）

杜绝“自己创作自己审核”的双重标准：

  • 生成Agent：专注创意、剧情、对话产出

  • 评审Agent：独立校验三层规则：人设一致性、人物关系逻辑、时序剧情无冲突

校验不通过自动返回修改意见，迭代重写，直到合规再入库。

八、关键难题解决：剧情修改、多支线时间线、数据同步

1. 修改旧章节，如何自动同步RAG知识库？

核心方案：所有知识库条目绑定唯一DocID

  • 修改剧情后，Updater根据ID删除旧向量、旧文本

  • 新内容重新分片、打标、向量化、覆盖入库

  • 联动更新：角色动态履历 + 人物关系图谱 + 时序时间线

实现「改一处、全库自洽」。

2. 无统一时间线、多支线并行如何处理？

不用强行统一全局时间线，采用分层时序架构：

  • 主线时序库（最高优先级，全局强制遵守）

  • 各支线独立时序库（支线内部自洽，互不干扰）

评审Agent只做两件事：支线内部无矛盾、支线不违背主线关键事件。完美适配网文多支线、多视角叙事。

九、落地结论：从零到一的架构升级路径

1. 纯Prompt阶段：靠人力兜底，必然偏移、幻觉严重

2. 基础RAG阶段：解决遗忘、稀释问题，但无审核、无同步、无迭代

3. Agent自治阶段：记忆+规划+生成+评审+更新闭环，彻底解决人设偏移、剧情失控

十、最终总结（核心心法）

1. 大模型是“无记忆、无逻辑、无底线的创作者”，必须靠架构约束；

2. RAG解决「记不住、被稀释」的问题，分层Prompt解决「优先级混乱」的问题；

3. 只有独立评审Agent能兜底幻觉与细微OOC；

4. 动态更新机制解决剧情迭代、数据不同步；

5. 多分层时序架构适配所有复杂网文、游戏叙事结构。

真正的AI创作能力，不是会写提示词，而是会搭建一套让AI永远不跑偏的系统。
