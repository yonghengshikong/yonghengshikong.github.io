小说叙事Agent高级RAG检索体系：权重分层+双路召回+动态裁剪，根治长篇人设稀释与剧情漏召

小说叙事Agent高级RAG检索体系：权重分层+双路召回+动态裁剪，根治长篇人设稀释与剧情漏召

前言

在搭建小说 / 游戏剧情生成 Agent 的过程中，很多人止步于基础 RAG：把角色、剧情分片存入向量库，依靠单纯向量相似度检索，就以为能解决人物 OOC、剧情幻觉。
实际落地长篇连载后会暴露两大致命短板：

  1. 多角色同场、海量支线剧情下，次要对话、细碎场景挤占角色档案 Token，核心人设权重被稀释，角色行为逐步跑偏；

  2. 纯语义向量检索存在随机性，角色姓名、专属羁绊、主线关键事件极易漏召回，AI 因缺少前置设定凭空编造剧情、人物恩怨。

Day7 完整学习了面向叙事场景的生产级 RAG 检索三层优化架构：素材权重分层、标签 + 向量双路混合召回、检索后置重排与 Token 动态裁剪。这套机制是叙事 Agent 底层核心，从输入源头降低偏移与幻觉，搭配循环校验、工具更新模块，才能支撑百万字长篇稳定创作。

一、单一向量检索的天然缺陷（网文创作专属痛点）

仅依靠向量相似度检索，无法适配多角色、多支线、可修改剧情的小说场景，三大硬伤无法规避：

  1. 无信息优先级区分，核心设定被稀释
    向量只判断语义相近程度，不会区分 “主角硬性人设” 和 “路人无关日常”，大量低价值支线文本抢占上下文空间，模型注意力偏向剧情，弱化角色底层约束。

  2. 实体信息召回不稳定，关键剧情随机丢失
    角色 ID、专属恩怨、决定性主线事件属于精确实体信息，仅靠语义匹配极易漏招；缺少关键过往经历，是 AI 编造虚假身世、反转关系的核心诱因。

  3. 多支线时序互相干扰，逻辑冲突频发
    主线、多条支线素材混杂存储，检索时无时间线隔离，无关支线剧情混入 Prompt，造成时间线悖论、人物行为前后矛盾。

想要实现稳定可控的叙事生成，必须给检索链路叠加三层标准化优化。

二、第一层优化：知识库素材权重分层设计

入库阶段给每一条向量文档绑定数字权重，从根源划定信息优先级，检索后强制高权重内容优先保留，次要素材可按需裁剪，完美适配小说分层信息结构。

叙事场景四级权重标准

  1. 权重 10（最高强制保留，不可裁剪）
    主角完整人物档案、世界观底层规则、主线决定性转折、角色核心行为底线。

  2. 权重 7（高优尽量保留）
    重要配角档案、核心人物两两羁绊、立场反转、重大恩怨剧情。

  3. 权重 3（次要，Token 超限优先删减）
    支线常规事件、次要配角日常互动、通用场景描写。

  4. 权重 1（补充素材，资源不足直接舍弃）
    路人对话、无冲突细碎日常、无关环境铺垫。

配套执行规则

  1. 所有权重≥7 的文档锁定，无论上下文是否超限，必须注入 Prompt 约束区块；

  2. 仅权重 3、1 的素材参与动态裁剪，删减顺序从最低权重开始；

  3. 所有角色相关文档统一拉高权重，杜绝剧情片段覆盖人设。

三、第二层优化：双路混合召回（标签强制召回 + 向量语义召回）

单一检索存在盲区，行业标准采用两路并行召回，结果合并去重，兼顾精确实体匹配与软性语义关联，彻底杜绝关键角色、主线事件漏招。

1. 标签强制召回（确定性兜底，解决实体丢失）

每条入库素材绑定结构化元标签：角色 ID、timeline_group 时间线分组、事件类型、所属势力、人物关系。
执行逻辑：系统识别本次出场角色列表、当前写作所属主线 / 支线，根据角色 ID 批量拉取全部绑定该角色标签的文档，100% 全量取出。
核心优势：不受语义相似度干扰，只要文档绑定角色标签，一定会被召回，彻底解决角色过往经历遗漏。

2. 向量语义召回（补充隐性关联剧情）

将本次写作需求转为向量，在向量库匹配语义相近的场景、冲突、伏笔桥段，补充标签无法覆盖的软性剧情关联，丰富故事逻辑铺垫。
核心优势：捕捉同义词、相似冲突、隐性伏笔，让剧情过渡自然，不会生硬割裂。

两路召回不可单独使用的原因

  • 只保留向量检索：角色、关键主线事件随机漏招，信息缺失诱发大量幻觉；

  • 只保留标签检索：只能匹配固定实体，无法自动关联相似剧情、伏笔，剧情单薄、缺少铺垫。

合并流程

标签召回素材集合 + 向量语义召回素材集合 → 去重合并，生成候选素材池。

四、第三层优化：检索后置重排序与 Token 动态裁剪

两路召回合并后素材总量极易超出上下文窗口上限，直接拼接依旧会出现信息稀释，必须增加后置过滤流程，四步标准化处理：

  1. 去重：同一角色档案、同一段剧情重复召回仅保留一份，减少冗余 Token 占用；

  2. 权重重排：所有权重 10 置顶，其次权重 7，最后次要素材，让模型优先读取不可篡改的硬性设定；

  3. Token 总量测算：实时统计所有候选素材总字符 Token；

  4. 梯度裁剪：从权重最低文档依次删减，直到总素材 Token 低于预设阈值。

兜底保护规则

裁剪过程中不允许删除权重≥7 核心素材；若删减后依旧超限，自动缩短单次生成剧情篇幅，保证人设完整。

多角色同场专属适配逻辑

单段剧情出场 5 人以上高频场景：

  1. 批量标签召回全部角色档案、两两人物关系；

  2. 向量检索匹配多人共同参与的主线事件；

  3. 路人、次要配角素材做精简压缩，优先保障主角、核心配角人设完整。

多支线无统一时间线适配逻辑

大量小说不存在全局统一线性时间轴，采用时间线标签隔离方案：

  1. 强制拉取全部主线高权重事件，主线规则全局生效，所有支线不能违背主线设定；

  2. 仅召回当前写作所属支线剧情，过滤其他无关支线素材，避免多条支线互相干扰；

  3. 上层评审 Agent 额外校验支线剧情与主线关键事件无逻辑冲突。

五、完整检索全链路（小说 Agent 标准流水线）

用户输入章节写作需求

  1. 语义解析识别出场角色列表、当前所属主线 / 支线时间线；

  2. 标签强制召回：所有出场角色档案、主线高权重固定事件；

  3. 向量语义召回：匹配相似场景、关联伏笔、同类冲突剧情；

  4. 两路素材合并、去重，按照预设权重降序重排；

  5. 实时测算总 Token，梯度裁剪低权重次要素材；

  6. 筛选完成的合规素材自动填入分层 Prompt 约束区块，送入 LLM 生成剧情。

六、这套检索架构解决的核心痛点复盘

  1. 解决长篇人设稀释：权重分层保证角色档案、世界观规则永远优先展示，不会被海量支线剧情覆盖；

  2. 解决角色、关键剧情漏召回：标签强制兜底，不受向量相似度波动影响；

  3. 解决多支线剧情混乱：时间线标签隔离无关支线，仅保留主线 + 当前支线素材；

  4. 严格控制上下文 Token 总量：动态裁剪平衡素材丰富度与窗口上限，兼顾创意与人设稳定。

七、简易 RAG 与叙事级优化 RAG 的本质差距

基础简易 RAG 仅做「向量检索 + 简单文本拼接」，属于单向输入优化，存在不可逆缺陷：

  1. 关键角色、主线事件随机漏招，幻觉频发；

  2. 次要素材挤占核心人设，长篇连载持续 OOC；

  3. 多支线混杂，剧情逻辑容易自相矛盾。

权重分层 + 双路混合召回 + 后置裁剪属于叙事专用生产级 RAG 方案，是搭建稳定小说 Agent 不可或缺的底层基础；仅依靠这套检索体系只能优化输入素材，想要完全杜绝偏移，还需要搭配循环迭代校验架构、Function Call 知识库自动更新模块，形成完整自治智能体闭环。

结尾总结

想要 AI 写长篇小说、游戏剧情不 OOC、不编造虚假内容，单纯优化提示词、调整模型温度参数治标不治本。检索层精细化设计才是底层根基：
权重分层解决信息优先级失衡，双路召回解决关键信息遗漏，重排动态裁剪解决上下文稀释。三者组合形成可控、稳定的素材供给链路，从源头大幅降低角色偏移与幻觉概率，再依靠上层评审 Agent 做最终兜底，支撑几十万、上百万字长篇连载逻辑完全自洽。
